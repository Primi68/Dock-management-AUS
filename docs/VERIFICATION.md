# 검증 범위

0.3.3 미리보기의 업무 규칙 테스트 23개와 모바일 브라우저 시나리오 16개를 자동 실행합니다. Android 15(API 35) 에뮬레이터에서도 인터넷 권한 없이 앱을 열고, 기기 저장 후 Activity를 재생성해 작성 중 기록이 복구되는지 검사합니다. 최종 배포는 모든 CI 작업의 성공을 조건으로 합니다.

- Node: 15분 전 추천, 주말, 누락된 회차, 자정 마감, 이전 기록 독립 복사, 전체/부분 강조, 반출, 구역 유효성, 최대 3개 코드, 백업 검증, 텍스트 출력.
- Playwright: 모바일 크기로 작성 → 재실행 → 저장 → 다음 점검 → 상태 변경 → 컨테이너 교체 → 반출, 구역 설정, 이력, 백업 복원, 320px 가로 넘침 확인.
- Android: Gradle APK 조립 및 lint. CI 결과는 GitHub Actions에서 확인.

실제 Android에서 추가 확인: 한글/영문 키보드, 하단 버튼과 키보드 겹침, 잠금·앱 전환·회전 후 작성 유지, 오프라인 저장·재실행, 시스템 클립보드와 파일 선택기, 업데이트 전 백업과 복원.

브라우저 테스트를 실제 사용자 휴대전화 검증으로 표현하지 않습니다. 테스트 예시는 DEMO-* 가상 값만 사용합니다. 사진 및 동기화는 미구현 범위입니다.

0.2 추가 검증: Ready to drop 취소/확인과 완전 비우기, 실수로 만든 15:30 임시 기록 취소 후 11:30 수정, 수정 중 재실행, 이후 기록 보존, 최신 점검 삭제, 수정 취소, populated Dock 10개 이상 표시, 9~13 및 14~20 구간의 정확한 범위.

0.2.1 추가 검증: Ready to drop 복구/다시 실행과 재시작, 컨테이너 교체의 원자적 복구, 타이핑 묶음과 키보드 단축키, 새 입력 시 redo 초기화, 저장 시 내역 종료, 50단계 제한 및 잘못된 undo 백업 거부.


0.3 추가 검증: 한국어↔영어 전환과 취소, 앱 재실행·JSON 복원 후 언어 유지, 구버전 백업의 한국어 기본값, 알 수 없는 언어 거부, 사용자 입력·구역 제목·작성 중 되돌리기 보존, 영어 변경 배지·이력·내보내기·날짜 오류·백업 오류·반출 확인, 320px 영어 화면 가로 넘침 방지. Android 에뮬레이터에서는 실제 설정 UI로 영어를 저장하고 Activity 재생성 뒤 언어·버튼·기록 유지와 네이티브 저장값을 확인합니다.

초기 CI에서 시스템 글꼴 차이로 드러난 좁은 영어 화면의 가로 넘침은 상단 줄바꿈과 입력 영역 최소 너비 조정으로 수정했습니다. 최종 버전 검증은 [v0.3.3-mvp 태그 실행](https://github.com/Primi68/Dock-management-AUS/actions/workflows/android.yml?query=branch%3Av0.3.3-mvp)에서 확인할 수 있습니다. 실제 사용자 휴대전화에서의 키보드·파일 선택기 테스트는 별도입니다.


0.3.1: 메뉴의 설정에서 언어 설정과 점검 시간·구역 설정을 각각 열어 독립된 입력 항목인지 확인합니다. 기존 12개 화면 시나리오는 새 탐색 경로로 검증하며, Android 재생성 검증도 설정 → 언어 설정 경로를 사용합니다.


0.3.2: 모바일 브라우저에서 상단 ↓ 버튼 위치, 클릭 후 Dock 20이 하단 저장 버튼에 가려지지 않는지, 이동 전후 저장 데이터 동일 여부, 조회 화면에서 버튼을 숨기는 동작을 확인했습니다. 기존 업무 로직 20개·화면 시나리오 12개와 Android 빌드/lint·에뮬레이터 검증을 실행합니다.

0.3.3: 기존 번호가 남아 있는 점검에서 코드를 먼저 입력한 뒤 번호를 바꿔도 모든 Dock 1~20의 관찰 내용이 유지되는지 검사합니다. 빈 번호의 늦은 입력, 코드 3개 보존, 입력 도중 백업·재실행, 번호 정정 후 새로 쓴 메모 보존, 새 컨테이너 강조 복귀, 명시적 초기화의 취소·확인·재실행·되돌리기·다시 실행, 한국어/영어 및 좁은 화면, 구버전 자동 비우기 복구 정보도 포함합니다. Android 에뮬레이터 시나리오는 Dock 14 번호 변경 후 네이티브 저장·Activity 재생성·초기화 취소와 확인·재생성 후 되돌리기를 추가합니다. 이전 점검과 생성 당시 비교 기준의 독립성을 확인하며 테스트 데이터는 모두 가상 값입니다.

회사 PC의 제한된 실행 환경에서는 Node 자식 프로세스의 `spawn EPERM`으로 일반 화면 테스트가 시작되지 않아, 핵심 테스트는 단일 프로세스 모드로 실행합니다. 원래 명령의 핵심·화면 테스트 및 최종 Android 에뮬레이터 검증은 GitHub Actions에서 수행합니다.
