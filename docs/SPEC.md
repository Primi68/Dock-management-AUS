# Dock Notes — MVP 명세 0.1

사용자 대화에서 합의한 범위의 첫 프로토타입입니다. 실제 사용 피드백으로 개선합니다.

## 목적과 범위

본인 한 명이 Android 휴대전화로 현장 점검 내용을 적습니다. 사무실에서 이 기록을 보고 WMS의 컨테이너 번호와 아이템 코드를 현물과 대조합니다. WMS에서 컨테이너 번호 / shipment number / itemcode 1~3을 복사하여 회사 PC 엑셀에 붙여넣습니다. 앱은 현장 기록장이고 공식 WMS나 엑셀의 대체 시스템은 아닙니다.

원칙: **노트앱의 자유로움을 유지하면서 반복 작업만 줄이는 것.**

## 일상 흐름

`다음 점검 →`을 한 번 누르면 날짜와 점검 시간을 자동 지정하고 최근 저장 기록의 Dock 1~20을 즉시 복사합니다. 별도 생성 확인은 없습니다. 예외적인 날짜나 시간만 작성 화면의 `날짜·점검 시간 수정`에서 바꿉니다. 현장에서 달라진 부분만 수정하고 `저장 · 점검 보기`를 누르면 변경 강조가 유지된 읽기 화면으로 전환합니다. 이 화면을 보며 엑셀 작업을 합니다. 작성 중인 점검이 있으면 새 복사본 대신 이어서 엽니다.

변경하지 않은 값은 그대로 유지됩니다. Dock별 확인 버튼이나 입력 완료 강제는 없습니다. 각 입력 변경은 자동 임시 저장하며, 저장 버튼은 기록 확정과 읽기 화면 전환 역할입니다. 저장 실패는 성공으로 표시하지 않습니다.

## 화면과 입력

항상 Dock 1~20 오름차순입니다. 아침에는 1번부터, 다른 때에는 아래로 스크롤해 20번부터 확인할 수 있습니다. 이동 순서를 강제하지 않습니다.

초기 구역: Tires 1~8 / Dunnage 9~12 / 쓰레기 13 / Wheels 14~20. 제목과 Dock 번호는 고정 라벨로서 커서가 들어가지 않습니다. 구역 이름과 범위는 설정에서만 바꿉니다. 범위는 1~20을 순서대로 중복·누락 없이 포함해야 합니다.

각 Dock: 컨테이너 번호, 아이템 코드 최대 3개(기본 1칸), 자유로운 내용물, 상태, 선택 메모. 코드별 수량과 shipment number는 입력하지 않습니다. 번호를 나중에 확인할 수 있도록 미입력 저장도 허용합니다.

상태: Full / In process / Empty / Ready to drop. Empty는 컨테이너는 있지만 내부가 비었음, Ready to drop은 컨테이너 자체가 없음입니다. rtd·none과 같은 개인 표현은 Ready to drop으로 통일합니다. 상태 미입력도 허용합니다.

**Dunnage 별도 시간 규칙은 없습니다.** 매번 모든 Dock을 불러오고 사용자가 필요한 것만 수정합니다.

## 변경 비교

이번 기록 생성 당시 복사한 이전 점검의 스냅샷만 비교합니다. 엑셀 반영 완료 표시나 엑셀 기준 비교는 없습니다. 이전 강조는 복사하지 않고 현재 값의 차이로 계산합니다.

| 상황 | 동작 |
| --- | --- |
| 다른 컨테이너 번호 | 이전 코드·내용물·상태·메모를 비우고 새로 입력. 전체 노랑 + 새 컨테이너 배지 |
| 같은 컨테이너의 상태·코드·내용물·메모 변경 | 바뀐 항목만 노랑 |
| 컨테이너 반출 | Ready to drop 선택, 확인 후 현재 번호·코드·내용물·메모 비움. 전체 노랑 + 컨테이너 없음 배지 |
| 번호 오타 정정 | 같은 컨테이너·번호 정정 선택. 다른 값 유지, 번호만 강조 |
| 동일하거나 이전 값으로 복귀 | 해당 강조 없음 |

컨테이너 식별 비교는 대소문자와 연속 공백을 정규화합니다. 우연히 같은 제품이어도 다른 컨테이너로 취급합니다. 이전 값을 펼쳐볼 수 있고 읽기 화면에서 변경된 Dock만 필터링할 수 있습니다. 첫 점검은 빈 기록과 비교합니다. 과거 기록은 보존하고 최신 저장 점검만 다시 수정할 수 있습니다.

## 날짜·점검 시간

기본 월~금, 07:30 / 09:30 / 11:30 / 13:30 / 15:30. 휴대전화의 로컬 날짜와 시간대를 사용합니다. 예정 시각 15분 전부터 해당 점검을 추천합니다. 실제 생성·저장 시각은 점검 시간과 별도입니다.

- 09:15 시작 → 당일 09:30.
- 13:15 시작 → 중간 점검을 놓쳤어도 당일 13:30.
- 금요일 15:30을 저장한 뒤 다음 점검 → 월요일 07:30.
- 주말 후 월요일 아침 → 월요일 07:30. 주말 가짜 기록 생성 없음.
- 아직 다음 점검 15분 전이 아니면 직전 도래 점검을 제안하여 지연 입력 허용. 이미 기록이 있으면 다음 미작성 슬롯 제안.
- 선택 설정 24:00은 해당 업무일 마감. 다음 날 00:00~00:30에는 전날 마감을 제안할 수 있음.

시간·근무일은 설정에서 변경 가능합니다. 공휴일 자동 인식은 없습니다. 작성 화면에서 날짜/시간을 수정할 수 있습니다. 중복 슬롯 또는 최신보다 과거인 새 기록은 방지합니다. 설정 변경은 새 점검부터 적용하고 과거 시간과 구역을 보존합니다.

## 저장과 내보내기

앱 전용 내부 저장소에 원자적 JSON 저장. 인터넷 통신이나 자동 업로드 없음. 최신 점검 전체 복사, 현재/전체 이력 텍스트 저장 지원. JSON 백업은 설정·기록·작성 중 내용·비교 기준을 포함합니다. 복원은 검증 후 확인을 받아 현재 데이터를 교체합니다. 앱 삭제/기기 변경 전 JSON 백업이 필요합니다. 텍스트는 읽기용, JSON은 복원용입니다. 백업 최대 20MB. 저장 위치는 사용자가 시스템 파일 창에서 선택합니다.

## 후속 개발 후보

사진 첨부와 사진 포함 백업, 팀원 실시간 공동 사용, 실제 회사 환경과 정책에 따른 엑셀/WMS 연동 가능성 검토, 실제 엑셀 양식의 XLSX 내보내기. MVP에는 구현하지 않습니다.

## 수용 기준

1~20 순서 유지, 설정 제목에 커서 없음, 이전 데이터와 강조의 독립성, 전체/부분/반출 구분, 코드 최대 3개, 재실행 후 작성 이어가기, 백업 복원 무결성, 잘못된 백업의 덮어쓰기 방지, 모든 개발/배포 산출물의 실제 운영 정보 제외.
